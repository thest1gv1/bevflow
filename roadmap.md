# BevFlow Roadmap

## Сделано

### Основа проекта

- настроен проект на Next.js 16, React, TypeScript и Tailwind CSS;
- подключены и используются UI-компоненты shadcn/ui;
- подготовлен PostgreSQL для локального запуска через Docker Compose;
- добавлен шаблон переменных окружения `.env.example`;
- подключены Drizzle ORM и PostgreSQL-драйвер;
- добавлены конфигурация Drizzle и команды для работы с базой;
- описана таблица `products` и enum статуса;
- создана и применена первая миграция;
- добавлен seed-скрипт с тестовыми товарами.

### Модуль Products

- создан тип `Product`;
- добавлены тестовые данные товаров;
- реализовано табличное отображение на больших экранах;
- реализовано карточное отображение на небольших экранах;
- добавлен поиск по названию и бренду;
- добавлена фильтрация по статусу товара;
- добавлена сортировка по названию, остатку, закупочной цене и цене продажи;
- статус товара и складской остаток отображаются независимо;
- реализована форма добавления товара;
- добавлена клиентская проверка полей формы;
- новые товары добавляются в локальное состояние React.

## Сейчас

### Подключение Products к базе данных

Текущая цель — перевести чтение и добавление товаров с локального состояния на PostgreSQL.

План текущего этапа:

1. Получать каталог товаров из базы на сервере.
2. Удалить зависимость страницы от локальных тестовых данных.
3. Подключить добавление товара к базе через серверный слой Next.js.
4. Выполнять повторную валидацию данных на сервере.
5. Создавать `id` и начальный статус товара на стороне сервера или базы данных.

На первом этапе поиск, фильтрация и сортировка могут оставаться на клиенте. Их перенос на сервер будет выполнен отдельно, когда базовая работа с PostgreSQL станет стабильной.

## В планах

### Завершение CRUD для Products

- редактирование товара;
- переключение статуса `active` / `inactive`;
- удаление товара с подтверждением;
- обработка ошибок операций;
- отображение состояния загрузки;
- уведомления об успешных операциях.

После появления редактирования общую разметку полей следует вынести из `AddProductDialog` в переиспользуемую форму товара.

### Работа с большими каталогами

- серверный поиск;
- серверная фильтрация;
- серверная сортировка;
- пагинация;
- загрузка только необходимой части данных.

### Архитектура и производительность

- измерить поведение рендеринга после завершения основной функциональности;
- оставить интерактивные части клиентскими компонентами;
- перенести получение данных и подходящую логику в серверные компоненты;
- оптимизировать компоненты только при наличии измеряемой проблемы.
